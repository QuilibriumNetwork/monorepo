# Quilibrium patches

Vendored from `libp2p-autonat` 0.15.0 as published on crates.io (rust-libp2p). The published source, normalized manifest and original manifest are retained. Local changes are marked `QUILIBRIUM:`.

The package is a workspace member, so its unit tests run with the workspace tests. The integration tests in `tests/` need `libp2p-swarm-test`, which the published manifest drops; their targets and the dev-dependencies only they use are removed from `Cargo.toml` (the files are kept for reference), and a `libp2p-identity` dev-dependency with `rand` serves `PeerId::random` in the unit tests.

## Inbound dial-back racing a disconnect

`src/v1/behaviour/as_server.rs` (`resolve_inbound_request`): upstream `.expect`s the sender to be connected, but a dial-back request can arrive on a connection whose `ConnectionClosed` was already handled. The panic stopped the whole swarm task. The missing sender is answered with `DialRefused` instead, and the client retries with another server.

## Dial-back failures

`src/v1/behaviour/as_server.rs` (`dial_back_failure`, `start_dial_back`, `take_failed_dial_back`): upstream answered `DialError` to the client whenever any dial to it failed while its request was pending, including another behaviour's dial and a dial-back this server refused itself. The connection limits deny a connection to a peer that already holds the maximum (two on Quilibrium nodes), which is common between nodes that dial each other, so reachable clients saw most probes fail and AutoNAT held them private. The server now records each request under its dial-back's connection id, ignores failures of other dials, answers `DialRefused` (no change of the client's status) when it denied, aborted or skipped its own dial-back or has no transport for any of the addresses, and `DialError` only when the dial-back reached none of the addresses or another peer. The ongoing requests are a struct instead of a tuple, so the helpers can be tested without a response channel.

`ServerStats` and `Behaviour::take_server_stats` count what the server did (served, failed, refused by reason, failed exchanges) for an hourly operator line of the node, with the distinct clients served and failed, the failures by the class of the first address tried (transport and default, worker, ephemeral or other port) and by why the dial-back failed (refused, timeout, reset, no route, wrong peer), and the clients that failed most.

## Short dial-back address list

`src/v1/behaviour/as_client.rs` (`probe_addresses`): a probe offers the listen addresses first, one per protocol stack after the IP (the server replaces the IP with the one it observes, so the port is what counts), then the external candidates, most recent first, at most 8 addresses, and never more than the server's 1024-byte frame limit (`src/v1/protocol.rs`, `MAX_MESSAGE_LEN`). Upstream sent every candidate ever observed, in hash order, ahead of the listen addresses. Peers behind address translation report many different ports for us; the server keeps the first 16 and dials them one at a time, so a reachable node's probes timed out on closed ports, and once the candidates outgrew the frame limit no server could read the request. Probe failures of that kind leave the NAT status unchanged, so a node that missed its first probes stayed unconfirmed until restart.

`src/v1/behaviour.rs`: the candidate set is insertion-ordered (a repeated candidate moves to the front) and keeps the 16 most recent (upstream: an unbounded hash set that never forgets an address). Two read-only accessors serve operator logging: `last_probe_addresses` (the latest request's list) and `eligible_servers` (the servers the next probe can choose from). Protocol, probe rate and server behaviour are unchanged.

## Dial-back address shapes and budget

`src/v1/behaviour/as_server.rs` (`filter_valid_addrs`, `PlainAddr`): the server dials back only plain TCP and QUIC addresses (`/ip{4,6}/<ip>/tcp/<port>[/p2p/<peer>]`, `/ip{4,6}/<ip>/udp/<port>/quic-v1[/p2p/<peer>]`, port not zero), rebuilt from the IP it observes for the client. Upstream replaced only the first IP of each address and dialed the rest as given: a second, stacked IP, a name to resolve, or a protocol layered on top.

`src/v1/behaviour.rs` (`Config`), `src/v1/behaviour/as_server.rs` (`admit_dial_back`, `request_failed`, `take_stale_dial_backs`): a server tries at most 8 addresses per request (`max_peer_addresses`, upstream 16; the most this repository's clients send) and runs at most 16 dial-backs at once whose request is open (`max_concurrent_dial_backs`, new), one per client, one per client IP and two per client IP group (an IPv4 /24 or an IPv6 /48, `ip_group`, `DIAL_BACKS_PER_GROUP`), whatever the peer IDs behind it; a request beyond any limit is answered `DialRefused`. One per client alone let a host with a few identities, asking for addresses that never answer, hold the whole budget; one per IPv6 /64 let one holder of a /48 (a usual site allocation, free from a tunnel broker) do the same, and one per IPv4 address the holder of a rented /28. One per group let one address in another node's /24, keeping a dial-back in progress at every server, have that node's every probe refused; two per group make that take two addresses there. The remaining bound: to hold all slots of every server, an attacker needs 16 IPs in 8 IPv6 /48s or IPv4 /24s, each keeping a request open, the same 16 serving against every server. Clients at an IP, or in a group, with dial-backs running get `DialRefused`, which leaves their status unchanged; the client's observer list also groups IPv4 by /24 (see below), the node's server list and address tracker by address. Each dial-back holds an outbound dial slot until it connects or its last address times out. Once its request failed (it timed out, or the client closed it) it answers no one and gives its place among the 16 at once, but it keeps its client, its IP and its place in its group until its dial ends and counts against twice the budget in all, so at most 32 dial-backs run (upstream dropped it then, so a client that let its requests time out could keep any number of dials running). An entry the swarm never reported ended is dropped at the next request once it is `max_dial_back_age` old (new, 160 s: twice the longest dial-back at the default connection timeout), so a missed report cannot hold a place for good. Only the dial-back's own connection (`take_reached_dial_back`, by connection id) answers it as reached; upstream took any outbound connection to the client on a requested address, so another behaviour's dial there freed its place while the dial-back still ran.

## Answers naming an address the probe did not offer

`src/v1/behaviour/as_client.rs` (`answers_probe`, `OngoingOutbound`), `src/v1/behaviour.rs` (`note_observed_address`): a server's `Ok(address)` confirms the address only when it is plain (as above), carries no other peer's id, names the transport and port of an address the probe offered, and an IP of a listen address or one a peer other than that server observed the node at (the embedder reports identify's observed addresses with the observer's remote IP; the 64 most recent are kept, one per peer and per observer IP group, an IPv4 /24 or an IPv6 /48, so one host or one rented block with many peer IDs pushing identify holds one entry and cannot evict the others; by IPv4 address, the 64 addresses of one /26 evicted them all). External candidates do not vouch for an IP: identify takes them from any peer, so a server could plant one and answer a probe of it. The observer check is no bound on its own: the second peer can be another identity of the same operator, even on the server's IP. The bound is the embedder's tracker, which accepts an address only once servers on two IP groups (an IPv4 address or an IPv6 /48) confirmed it (see below). Any other answer is `OutboundProbeError::UnprobedAddress` (new) and leaves the status unchanged. Upstream confirmed whatever address the server named, so one server could set the node's external address.

## No external address from one answer

`src/v1/behaviour/as_client.rs`: an answer no longer emits `ToSwarm::ExternalAddrConfirmed`. The swarm announces its external addresses through identify, and peers add them to Kademlia, so one server's answer could set where peers dial the node. The embedder adds and removes the swarm's external addresses itself (`Swarm::add_external_address`, `remove_external_address`) from the addresses servers on two IPs confirmed. `Behaviour::probe_now` (new) sends the next probe at once, to a server not recently asked; the embedder calls it when a first address awaits its second server, which the schedule would ask a retry interval (90 s) later.

Regression tests: `as_client::tests`, `as_server::test` and `behaviour::tests`.
